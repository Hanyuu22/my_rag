# 毕业论文策略 & 项目定位

> 记录论文写作策略、项目双重定位（论文 vs 自学/面试）及后续重点方向。

---

## 一、项目的双重身份

| 维度 | 毕业论文 | 自学 / 面试项目 |
|------|---------|----------------|
| 数据集 | 老师提供的指定 PDF（单文档，受控实验） | 多领域知识库（能源报告、GB 国标、投资数据） |
| 评估标准 | 严谨、可重复、控制变量 | 工程规模、技术深度、方法论系统性 |
| 核心价值 | 方法对比有说服力，RAGAS 量化支撑结论 | 面试能讲清楚从 0 到 1 的完整链路 |
| 重点展示 | 检索策略对比 + RAPTOR 提升多跳能力 | V4 实验设计 + 跨语言检索 + 全栈工程 |

## 二、毕业论文应该怎么写

### 核心原则：聚焦指定文档，深做系统对比

老师给一个 PDF 是**优势**，不是局限——控制了数据变量，对比结论更可信。

**建议论文结构：**

```
第1章 绪论
  - RAG 技术背景，传统检索的局限
  - 本文的研究问题：如何在专业领域文档上构建高质量 RAG 系统

第2章 系统设计与实现
  - MinerU 文档解析 + VLM 表格补全
  - Hybrid Retriever（BM25 + Dense + RRF）
  - BGE Reranker 精排
  - LangGraph 多步 RAG 流程

第3章 实验与对比分析（重点）
  - 实验设计：控制变量，逐步叠加
    Level 1（纯Dense）→ Level 2（+Hybrid+Reranker）→ Level 3（+LangGraph+VLM OCR）
  - 评估指标：RAGAS 四维（Faithfulness/AnswerRelevancy/ContextPrecision/ContextRecall）
  - 切分策略对比：chunk_size 512 vs 1024
  - 高级检索：RAPTOR 对多跳问题的提升效果（期望 ContextPrecision 0.25 → 0.6+）

第4章 拓展实验（可选，加分项）
  - 泛化性验证：在多领域文档上测试（能源报告、GB 国标）
  - 跨语言检索能力（Level 7d）

第5章 总结与展望
```

### 关键论点：每一级改动都有数字支撑

已有数据（加氢裂化工艺规程）：

| 指标 | Level 1 | Level 2 | Level 3 | 趋势 |
|------|---------|---------|---------|------|
| Faithfulness | 0.743 | 0.780 | **0.858** | 每级提升 |
| ContextPrecision | 0.122 | 0.500 | 0.500 | Reranker 效果显著 |
| Q3 表格 Top1 | 0.244 | 0.244 | **0.849** | VLM OCR 关键突破 |

RAPTOR 完成后补充：多跳抽象题 ContextPrecision 变化（当前 0.25，目标 0.6+）。

## 三、要不要主动和老师说拓展数据的事

**建议说，但注意框架：**

不要说"我扩充了很多数据"（显得偏离任务），而是说：

> "我在完成指定文档评估的基础上，为了验证方法的泛化能力，额外在能源领域多文档场景和国家标准文献库上做了验证，结果显示……"

这样的表达：
- 优先完成了老师布置的任务 ✅
- 主动展示了更多工作量 ✅
- 有"泛化性验证"的学术价值，不是乱来 ✅

可以把拓展实验写进论文第4章作为加分项。

## 四、自学项目面试时聚焦哪里

面试中最有说服力的不是"我建了多大的库"，而是：

**最强的两个故事线：**

1. **系统化实验设计**
   > "我设计了控制变量的对比实验，用 RAGAS 四指标量化了不同检索策略的效果差异，发现 Reranker 让 ContextPrecision 从 0.12 提升到 0.50，VLM 表格补全让表格类问题 Top1 score 从 0.24 提升到 0.85。"

2. **发现问题 → 定位根因 → 解决方案**
   > "多跳抽象题 ContextPrecision 只有 0.25，根因是 chunk 截断导致跨段信息丢失。解决方案是 RAPTOR 摘要树：对现有 chunks 分层聚类+LLM 摘要，追加写入向量库，让全局性问题能在摘要层命中。"

**不需要过度强调的：**
- 知识库有多少个、文档有多少份
- 技术栈列表（会被追问细节，不如主动聚焦核心）
